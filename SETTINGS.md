# Wearables Manager 2 settings

Open **Wearables Manager Icon Rules** or **Wearables Manager Supported Figures** from the same Scripts folder as WM2. Full has both settings buttons; Menu retains **Icon Rules...**. Use the separate figure editor to manage recognition and child protection before opening Menu.

## Icon rules

When exactly one scene object is selected, Pattern starts with its label in **Exact label** mode. With no selection or several selections, the form stays blank and a notice explains how to use the selection. Manual rules remain available. **Use Selected Name/Label/AssetId** copies actual text into Pattern while keeping the chosen Match mode. Choose Match separately. Each button requires one eligible active object and is disabled when the pattern already equals that value, ignoring case; AssetId also requires a nonempty identifier. The actual assetId is displayed separately. These buttons refresh when the pattern or editing target changes. Bones are not selected-item icon targets; fitted clothing and props remain eligible.

Choose a PNG from the icon list, or **Browse PNG**. The file picker starts in this WM2 installation's `Resources` icons directory. An external PNG is copied into that directory under its original basename. If a different file already uses that name, you must choose another filename or cancel; existing files are never overwritten. Selecting the same canonical file already in Resources reuses it without copying. Failed/cancelled imports keep the current icon choice. Imported files stay available in Resources even if you later cancel the settings draft.

**Clear Draft** deselects the rule and clears the form without adding it. **Add Rule** adds the form as a new row in the draft list; **Update Rule** replaces the selected row. **Save** writes the draft list and also commits a changed valid form. **Cancel** discards settings edits. Clear Draft is useful for abandoning an invalid form or starting a new rule while viewing a legacy row.

All six modes compare literal text **ignoring case**, while retaining the spelling you enter:

- Exact internal name.
- Exact label, ignoring only a final numbered copy suffix such as `Hair (1)` or `Hair (2)`.
- Word in internal name.
- Word in label.
- Exact assetId, matching the complete identifier.
- Word in assetId.

A word pattern in any field must have an allowed boundary on **both sides**: start/end, whitespace, a digit `0`-`9`, a hyphen/dash (`-` or Unicode U+2010-U+2015), underscore, or `!`. `Duvet` matches `dForce Duvet`, `Duvet2`, `Duvet_cover` and `!Duvet!`, including case variants. It does not match `DuvetCover` or `CoverDuvet`. Regex characters have no special meaning. Word rules use the original label/name/assetId without removing copy suffixes. Asset punctuation `/`, `#`, `:`, `.`, `%` and backslash is ordinary literal text, not an added word boundary: `Tail` matches `DAZHorse2Tail` (digit boundary), but not `/Tail.dsf#Tail`. Exact assetId matches that complete value if it is the actual returned identifier.

Asset rules read only the documented **DzNode.assetId string property** (available since DAZ 4.8.1.18), unchanged. This is separate from `assetUri`, `assetSource`, CMS `DzAsset.assetID`, runtime `elementID`, the node name and its label. Missing, throwing or nonstring assetId values do not match and do not fall back to another identifier. No path decoding, URL splitting, URI normalization or globally unique identity is inferred. The property may contain a file-local identifier; a full file-qualified URI is a distinct value. The configured case-insensitive matching policy is WM2's choice, while the original spelling is retained. Asset patterns permit up to 2,048 characters; other patterns retain the 256-character limit. [DzNode API](https://docs.daz3d.com/public/software/dazstudio/4/referenceguide/scripting/api_reference/object_index/node_dz), [DSON asset addressing](https://docs.daz3d.com/public/dson_spec/format_description/asset_addressing/start).

Exact name wins before exact label, then exact assetId, then word rules, then legacy prefixes. Longer word patterns win; equal lengths favor label, then name, then assetId, then the earlier row. Existing rules retain their relative priority. Move Up/Down changes the final row-order tie. The editor rejects a new rule of the same kind and pattern, ignoring case; update the existing row instead. Older saved rows differing only by case remain intact, with a validation notice explaining that the earlier matching row wins. Supported-figure names keep their separate exact case-sensitive policy. Asset modes extend the schema 2 rule-kind vocabulary; older WM2 builds cannot interpret these new kinds. Current WM2 retains existing schema 1/2 name, label and legacy rules without rewriting settings during installation.

Previously saved prefix rules remain marked **Legacy**, with their original prefix boundaries and longest/label/earlier-row ordering. Their icon matching now also ignores case. Their forms remain read-only; you can move or remove them. Use Clear Draft to create an exact or word replacement. Saving retains untouched legacy rows.

The title is **Icon rules for [visible label] [internal name]**, with the internal name in square brackets after the visible label. It refreshes with the active editing item. The lower preview shows the item's picture and visible label as in Menu, with larger centered **Selected** and **On Figure** headings. It uses the same effective icon resolver as Menu and Full, including assetId rules: a valid custom PNG overrides the existing built-in image; a nonmatching or missing custom PNG keeps the built-in choice. Selecting a rule does not force a match or override a higher-priority rule. Valid changed forms are previewed without saving. There are no match statistics or internal-name row listings in the preview.

Click a preview picture to choose that item as the editor's active target. WM2 validates its live identity and owner, selects its highest-priority matching rule when available, or prefills an uncommitted Exact label form. **A changed valid form is first retained in the in-memory draft rule list.** Invalid or conflicting forms block switching and keep the current target/form until corrected or explicitly abandoned with Clear Draft. Save writes all draft changes; Cancel discards them. The current figure preview mode stays active during a target switch. Scene selection, wearable parent/FitTo, metadata, properties and Undo are unchanged; the target is internal to the editor. A deleted item or one reparented to another owner cannot be chosen through a stale preview tile.

**Preview Scene** resolves the selected item's owning figure and shows that figure's Menu items with pictures, including attached nonbone descendants and stored items with resolved recovery connections. Selecting a figure or bone shows this list immediately. Parent/storage ownership takes priority over FitTo; a live supported FitTo target is used only when the item has no parent/storage owner. Other figures' items are excluded. Menu and preview share the owner, protection and storage-reference readers. Preview reads pending legacy storage without prompting or adopting it; unresolved stored items stay omitted with a brief notice. When launched from Menu, preview reflects that dialog's current draft placement of items.

The preview refreshes on selection, target, pattern, icon and rule changes. A new Scene selection returns the editing target to Scene selection while retaining unsaved form edits. No selection, multiple selections, unsupported owners, empty item lists and unavailable images have concise states. Bounds limit a preview to 2,000 item rows and a scene to 20,000 nodes; indexed DAZ collections need no native JavaScript Array branding. Picture clicks edit rules and have no transfer actions; preview never changes Scene selection, parenting, FitTo, metadata or Undo.

A missing or unreadable configured PNG uses WM2's existing automatic icon choice. Native layout and rendering remain for user verification; source/mock tests do not launch DAZ.

## Supported figures

Fresh settings start with ten known Genesis internal names, through Genesis9. The four additional compatibility names in the supplied scripts (Genesis9_1 and Genesis10 variants) are no longer fresh defaults. Existing saved names remain intact. Select a custom independent figure or one of its bones and choose **Add Selected Figure**. A bone resolves to its owning figure. The editor shows **Internal name** separately from **Visible label**. Fitted wearables, props, groups and figures attached under another skeleton cannot be registered as independent owners.

Entries use exact internal names, so changing a label does not change recognition. Remove edits the draft registry. **Reset Genesis Defaults** adds missing Genesis entries while retaining custom entries.

When Menu cannot resolve a supported owner from the selected object, it offers the figure editor before opening its transfer dialog. Opening setup does not register or move anything: choose an eligible independent figure or bone, use **Add Selected Figure**, review child protection, then **Save**. A prop or group can reach setup but cannot itself be registered. Full, Take Off and Put On offer setup for an unsupported selected independent figure or bone. With no selection, select a figure first or use the separate editor.

After Save, WM2 reloads settings, checks for an active process, reads the current selection again, resolves its supported owner and checks for nested figures. If the selection is still unsupported, the transfer dialog stays closed. Cancel returns without opening it. An open Full transfer dialog retains its current figure registry, while saved protection applies immediately. Re-add a removed figure type before restoring its stored wearables.

Select a registry entry and open **Protected Children...** to edit excluded child names. The five existing Genesis attachment profiles are supplied by default. Exact internal names match within that figure's descendants, including same-name copies. Protection includes the child's subtree and any ancestor that would carry it into storage. Full, Menu, Take Off and Put On's removal path check again immediately before parenting or FitTo changes. Alt and transfer marks do not override protection. Already-stored items remain eligible for restoration.

An explicit new registry entry initially adds every currently attached nonbone descendant name, including clothing, props, nested/fitted attachments such as DAZ Horse2 Tail and children beneath bones. Names are merged into any profile retained from an earlier registration; an existing empty or partial profile cannot suppress this initial collection. Custom types already listed without a profile also receive an initial profile. An already registered type's empty or customized profile stays intact when reopened or re-added. Review the profile and **Remove Protection** for items you explicitly want to move. Automatic custom-graft safety still applies; unknown graft relations stay protected. Collection validates actual parent-child membership and does not exclude an attachment because its name is Tail or because it is a figure. Intrinsic skeleton bones remain immovable independently of this list and need no list entry. Review newly added attachments as needed.

Reopen WM2 after changing child protection to refresh its item lists. If nothing is eligible to move, a notice explains the protection/transfer-mark settings; WM2 creates no storage group or snapshot.

Select one or more attached items in Scene and click **Add Selected Children** to add their actual internal names. Alternatively, select the edited supported figure or any of its own bones and press the same button to fill every current attached nonbone descendant name missing from its profile. Existing entries stay in order, duplicates are omitted and repeated figure/bone selections expand each owner once. The editor reads selection at click time and validates the selected owner against the edited profile; foreign owners, their bones and unrelated/unattached items are skipped with an explanation. Broken, ambiguous or unavailable membership and size limits reject the batch without a partial draft. Same-type figure copies share the existing name-based profile; an unrelated similarly named prop cannot qualify as an owner. Figure/bone selection alone does not change protection, and prior removals remain until an explicit bulk Add can re-add currently attached items.

The child editor has no manual name field or Protect Name action. **Remove Protection** edits the current list; later additions preserve those removals. Child **Save** returns only that edited list to the parent draft, and child **Cancel** discards child edits. Parent Save writes settings; parent Cancel discards the whole draft. Existing saved profiles remain compatible.

## Saving settings

Save creates or updates `Resources/WM2 Settings.json`. It does not overwrite `Resources/Wearables Manager.json`. If another editor changed the settings, reload before saving. A newer settings schema is read-only. Repairing an invalid settings file retains its original backup and reports the backup path.

## Validation status

Schema 2 adds bounded protected-child profiles. Schema 1 migrates in memory while preserving every saved figure name and icon rule; the file changes only on an explicit Save. Installation does not rewrite user settings.

These settings changes have source tests and isolated mocks. Native DAZ4/DAZ6 dialog layout, PNG loading and filesystem behavior remain for user runtime verification; these checks do not launch DAZ. The earlier transfer hotfix remains included. The broader metadata/emissive repair candidate is separate and has not been installed with these settings features.
