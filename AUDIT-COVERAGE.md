## Native matrix still pending

Coordinated native source checks and focused diagnostics have now run in uniquely named isolated DAZ4/DAZ6 instances, using explicit `.dsa` paths and disposable scenes. Product main entrypoints were not executed. All owned test instances closed and the slot is released. Production processes and configuration were excluded. See CHECKPOINT.md for exact completed checks and native blockers; the wider matrix remains pending.

| Area | Required evidence |
|---|---|
| DAZ4 / DAZ6 | Exact source syntax load; versioned API availability; normal Full/Menu/Take Off/Put On/UI behavior. Node parsing is insufficient. |
| Native Undo / Redo | Parent, FitTo, collision, materials, metadata/data-item creation/removal, empty group removal; failure halfway; no nested/unrelated hold cancellation. |
| Shell / geograft | Regenerated surfaces, new surfaces, partial selection, missing/reassigned shell target, duplicate RootLabel preset targeting, changed UV, save/read/apply failures. |
| Identity / scene lifecycle | Save/reload, merge, clone duplicate IDs, missing/replaced/reparented nodes, QObject identity comparison. |
| Animated controls | Off at frame0, Off at frame20, On at frame0; verify keyframes/current-time behavior before choosing an animation restoration policy. The existing single-color snapshot policy is not redesigned. |
| Live controls | Actual light/emission/dForce property types, shader variants, missing shape, Freeze/smoothing, native SubD conversion and selection restoration. |
| Help / launch | Encoded local path through OS PDF handler; DAZ content-browser/toolbar launch of revised `.dsa` scripts; archived `.dse` never selected. |
| Backup lifecycle | Application-data location on both major versions, save/reload availability, physical retention through Undo. Cleanup/garbage collection remains deferred. |

Other native-dependent or product-policy questions are retained explicitly: renamed material recovery, fixed-name/default exemption profiles, restoring a shell after a user edited its material, and conflict-aware overwrite policy. They are not asserted to be resolved by mocks. RootLabel ambiguity needs a native preset fixture before changing save targeting.

## Proportional next version

Ship verified reliability fixes first. After native evidence, consider a small named outfit/work-mode feature using already loaded scene items and a compact diagnostics/help surface. Disk-backed outfit copies require separate loading and dependency design. Archmage integration can be a small idempotent participant API later; a transaction framework and broad storage redesign are unnecessary for this repair build. Existing multi-figure/nested storage, selective transfer and the advertised visibility/dForce/Freeze/SubD/smoothing/collision/light/emissive controls are existing capabilities, not new roadmap claims.

Product baseline: [Wearables Manager](https://www.daz3d.com/wearables-manager). [Readme](https://docs.daz3d.com/public/read_me/index/98000_98999/98795/start) records the July16 2025 older-version launching and nonhuman collision fixes.
